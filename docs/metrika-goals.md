# Цели в Яндекс Метрике: что завести в кабинете

Код отправляет события, но **сами цели создаются в интерфейсе Метрики** —
без этого события уходят в пустоту и в отчётах их не будет. После правки
названий старые цели перестанут получать данные: имена изменились.

Счётчик: значение `NEXT_PUBLIC_YANDEX_METRIKA_ID` в окружении сборки.
Источник имён — `src/lib/analytics.ts`, тип `AnalyticsGoal`. Если правите
имя в коде — правьте и здесь, иначе цель замолчит.

Ничего из перечисленного я в кабинете не менял: доступа туда у меня нет и
трогать его без вашего решения нельзя.

## 1. Что сломается, если не перезавести

| Старая цель | Что с ней стало |
|---|---|
| `lead_submitted` | **переименована** в `open_telegram_draft` — перестанет получать данные |
| `click_telegram` | **разделена** на `click_telegram_booking` и `click_telegram_channel` |
| `click_max` | **разделена** на `click_max_booking` и `click_max_channel` |

Старые цели не удаляйте сразу — по ним останется история. Просто заведите
новые рядом; когда накопятся данные, старые можно скрыть.

## 2. Цели типа «JavaScript-событие»

Тип цели в интерфейсе: **JavaScript-событие**, идентификатор — точно как
в столбце «Идентификатор», без пробелов и заглавных.

| Идентификатор | Название для отчёта | Когда срабатывает |
|---|---|---|
| `cta_booking` | Клик «Записаться» | любая кнопка записи: шапка, первый экран, мобильная панель, мобильное меню, карточки тарифов |
| `cta_schedule` | Клик «Расписание» | кнопка расписания на первом экране и ссылка «Всё расписание» в блоке расписания и цены |
| `start_form` | Начал заполнять форму | первое касание любого поля формы, **один раз** на экземпляр формы |
| `open_telegram_draft` | Открыл черновик заявки в Telegram | форма прошла проверку и открыла Telegram с набранным сообщением |
| `click_telegram_booking` | Написать в Telegram (запись) | личный чат администратора — сюда пишут заявку |
| `click_max_booking` | Написать в MAX (запись) | личный чат в MAX |
| `click_telegram_channel` | Открыл Telegram-канал | публичный канал школы, его читают |
| `click_max_channel` | Открыл канал в MAX | публичный бизнес-канал |
| `click_vk` | Открыл ВКонтакте | публичная страница |
| `click_phone` | Клик по телефону | любая ссылка `tel:` на сайте |
| `click_route` | Построить маршрут | ссылка на карточку в Яндекс Картах |
| `view_contacts` | Дошёл до контактов | блок контактов появился на экране, один раз за загрузку страницы |

## 3. Цели типа «Посещение страниц»

Эти события кодом не отправляются намеренно: у страниц свои адреса, и
считать их ещё и событием значило бы считать одно и то же дважды.

| Название | Условие |
|---|---|
| Просмотр расписания | url: содержит `/raspisanie/` |
| Просмотр стоимости | url: содержит `/price/` |
| Просмотр страницы тренера | url: содержит `/trener/` |
| Просмотр страницы бассейна | url: содержит `/bassein/` |

## 4. Чего в кабинете заводить НЕЛЬЗЯ

**`lead_delivered`.** Сайт не доставляет заявку и не получает подтверждения:
форма открывает черновик, отправляет его родитель сам. Пока нет серверного
приёмника (см. `lead-delivery.md`), эта цель будет считать несуществующее.

**Составную цель «заявка» из `open_telegram_draft`.** Открытый черновик —
это намерение, а не заявка. Ровно из-за этого прежняя `lead_submitted`
завышала число лидов и занижала CPL.

## 5. Что смотреть, когда данные накопятся

Главный вопрос первых недель — где теряются люди:

```
визит → cta_booking → start_form → open_telegram_draft → (реальное сообщение в Telegram)
```

Последний переход сайт не видит — его можно оценить только сравнением
`open_telegram_draft` с числом сообщений, реально пришедших в чат за тот же
период. Эта разница и есть цена текущей схемы; она же — аргумент за или
против серверной доставки.

Полезно рядом: `start_form` против `view_contacts` — доходят ли до формы
вообще, и `click_telegram_booking` против `open_telegram_draft` — не проще
ли родителю писать напрямую, минуя форму.

## 6. Персональные данные

Ни одна цель не передаёт параметров: ни имени, ни телефона, ни возраста
ребёнка, ни комментария. Это проверено — в вызове `trackGoal` параметров
нет ни в одном месте кода. Не добавляйте их через интерфейс Метрики и не
включайте передачу содержимого полей форм: это персональные данные, а
согласие посетитель давал на аналитику посещений.

UTM-метки, `yclid` и адрес посадочной страницы Метрика собирает сама —
их сохранять можно и нужно, они не про конкретного человека.
