# Приёмник заявок: сайт → бот MAX

Функция принимает заявку с формы и отправляет её ботом в MAX, в чат школы.
Сайт собран статикой и лежит на GitHub Pages — серверного кода там нет,
поэтому форма обращается сюда по HTTPS.

```
форма → POST на функцию → проверка → бот MAX → чат школы
                                   ↓
                          номер заявки → «Заявка принята» + цель lead_delivered
```

Ключевое: **`lead_delivered` уходит только после ответа функции**. Если MAX
не принял сообщение, родитель видит ошибку и прямые контакты, а не «спасибо».
Из-за этого в отчётах Метрики видно ровно то, что школа реально получила.

## Почему Yandex Cloud Functions

Выбор площадки был открытым, поэтому — коротко, чем он обоснован.

| Вариант | Плюсы | Почему не он |
|---|---|---|
| **Yandex Cloud Functions** | серверы в РФ, бесплатного тарифа хватает с запасом, HTTPS и сертификат из коробки | — |
| Cloudflare Workers | проще всего запустить | серверы вне РФ. Заявка — персональные данные, а ч. 5 ст. 18 152-ФЗ требует обрабатывать данные россиян в России. Функция ничего не хранит, но спорить с РКН о том, считается ли приём «накоплением», дороже, чем взять российскую площадку |
| Свой VPS | полный контроль | нужно самому обновлять систему, следить за сертификатом и за тем, что процесс жив. Для одной формы это лишняя работа навсегда |
| Конструктор ботов (BotHelp, Salebot) | без кода | сценарий и переписка живут у стороннего сервиса — это отдельный обработчик персональных данных, которого пришлось бы указывать в политике и с которым нужно поручение на обработку. Ради одной формы это усложнение, а не упрощение |

Цена. Бесплатного тарифа Yandex Cloud Functions (миллион вызовов в месяц)
хватает на несколько порядков больше заявок, чем бывает у школы. Практически
счёт будет нулевым; платить придётся, только если функцию начнут долбить —
на этот случай в коде есть лимит частоты.

Код площадки не знает: вся логика в `handler.ts`, а `index.ts` — тонкий
переводчик формата события. Переезд на другую площадку означает переписать
один этот файл.

## Перед установкой

1. Бот создан через **@MasterBot** в MAX, токен получен.
2. Заведён чат, куда будут падать заявки, и бот в него добавлен. Можно и в
   личку — но отдельный чат переживает смену телефона, и в него можно
   добавить второго человека, не трогая настройки функции.
3. Кто-то написал в этот чат хотя бы одно сообщение — иначе бот не увидит
   события и не удастся узнать `chat_id`.

Узнать идентификатор:

```bash
MAX_BOT_TOKEN=ваш-токен node scripts/max-chat-id.mjs
```

Скрипт покажет `MAX_CHAT_ID` и `MAX_USER_ID`. Токен он никуда не сохраняет.

## Установка

**1. Собрать архив**

```bash
npm run build:lead
```

Появится `server/lead/dist/` (один файл `index.js`, внешних зависимостей нет)
и рядом `lead-function.zip`.

**2. Создать функцию**

В консоли Yandex Cloud: *Cloud Functions → Создать функцию*.

| Параметр | Значение |
|---|---|
| Среда выполнения | `nodejs22` (подойдёт и 18, и 20) |
| Способ загрузки | ZIP-архив `lead-function.zip` |
| Точка входа | `index.handler` |
| Таймаут | `15` секунд |
| Память | `128` МБ |
| Публичная функция | **включить** — иначе браузер не сможет обратиться |

**3. Задать переменные окружения функции**

| Переменная | Обязательна | Что это |
|---|---|---|
| `MAX_BOT_TOKEN` | да | токен бота от @MasterBot. **Секрет.** Только здесь |
| `MAX_CHAT_ID` | да, если нет `MAX_USER_ID` | чат, куда падают заявки |
| `MAX_USER_ID` | нет | личка вместо чата |
| `ALLOWED_ORIGINS` | нет | через запятую. По умолчанию `https://www.primeswim.ru,https://primeswim.ru` |
| `MAX_API_BASE` | нет | по умолчанию `https://platform-api2.max.ru`. Домен API уже менялся один раз, поэтому вынесен наружу |

Токен бота не должен попадать в репозиторий, в переменные GitHub Actions и
никуда с префиксом `NEXT_PUBLIC_` — последнее означало бы, что он напечатан
в исходнике каждой страницы сайта.

**4. Подключить сайт**

Адрес функции — `https://functions.yandexcloud.net/<id>`. Он не секрет:
всё равно виден в коде страницы.

GitHub → *Settings → Secrets and variables → Actions → Variables* →
переменная `LEAD_ENDPOINT` со значением адреса. Дальше — обычный push:
воркфлоу подставит её в сборку.

Пока переменной нет, форма показывает честную ошибку и прямые контакты.

## Проверка

Живая функция, с чужого адреса — должна отказать:

```bash
curl -i -X POST https://functions.yandexcloud.net/<id> -H 'content-type: application/json' -d '{}'
```

Ожидаемо `403`: без разрешённого `Origin` заявки не принимаются.

Настоящая проверка — с сайта: заполнить форму и убедиться, что сообщение
пришло в чат. Тестовую заявку в чате видно сразу, её же номер показан
родителю на экране.

Локально, без облака и без MAX:

```bash
# .env.local
NEXT_PUBLIC_LEAD_ENDPOINT=http://localhost:8788/lead
```

и небольшой приёмник, который вызывает тот же `createLeadHandler` с
подменённой доставкой (`deliver`) и `ALLOWED_ORIGINS=http://localhost:3000`.
Так проверяется вся цепочка, включая экраны успеха и ошибки, без единого
запроса наружу.

## Что функция отвечает

| Код | Когда | Что видит родитель |
|---|---|---|
| 200 | заявка ушла в MAX | «Заявка принята», номер |
| 200 + `duplicate` | повтор с тем же ключом | то же, вторая заявка не создаётся |
| 400 | поля не прошли проверку | ошибки под полями, теми же словами, что в форме |
| 403 | запрос не с сайта школы | — |
| 413 | тело больше 8 КБ | — |
| 429 | слишком часто | «слишком много заявок подряд», прямые контакты |
| 502 | MAX не принял сообщение | «не получилось передать», прямые контакты |
| 503 | не заданы токен или получатель | «приём заявок временно не работает», прямые контакты |

## Персональные данные

Заявка нигде не сохраняется: она уходит в MAX и забывается. В логи функции
идут только статус доставки и номер заявки — ни имени, ни телефона, ни
возраста, ни комментария. Это проверяется тестом (`handler.test.ts`).

Смысл не в аккуратности, а в том, чтобы не заводить базу персональных данных
там, где она не нужна: нет базы — нечему утечь, нечего локализовать и не за
что получить оборотный штраф.

Правовая часть (уведомление в РКН, политика, согласие) разобрана в
`docs/legal-checklist.md`.

## Границы решения

Честно о том, чего здесь нет.

- **Лимит частоты и защита от повторов живут в памяти экземпляра функции.**
  Холодный старт их обнуляет, у параллельных экземпляров счётчики свои. Это
  заслон от случайного дубля и примитивного скрипта, но не от распределённой
  атаки. Настоящий лимит потребовал бы внешнего хранилища — дороже, чем
  проблема, которую он решает при нескольких заявках в день.
- **Повторов доставки от сайта нет.** Повторяет только функция и только
  запрос в MAX. Родитель может нажать «Отправить» ещё раз — ключ запроса тот
  же, и вторая заявка не создастся.
- **Заявка не попадает в CRM.** Только в чат MAX. Офлайн-конверсии
  (`trial_booked`, `subscription_paid`) — отдельная задача.
