# PRIME SWIM — сайт школы плавания

Самостоятельный сайт школы плавания PRIME SWIM (Химки, бассейн МГИК), созданный
для ухода с Tilda.

> **Статус: опубликован.** Сайт работает на `https://www.primeswim.ru` —
> статика собирается на GitHub Pages воркфлоу `.github/workflows/deploy.yml`
> при каждом пуше в `master`. Голый `primeswim.ru` и любой заход по http
> отвечают постоянным редиректом на канонический адрес с www.
>
> Индексация открыта, счётчик Метрики подключён, права в Яндекс Вебмастере
> подтверждены метатегом в `src/app/layout.tsx`.

## Технологии

| Что | Зачем |
|---|---|
| **Next.js 16** (App Router) | Каркас сайта, генерация статических страниц, sitemap и robots |
| **React 19** | Компоненты интерфейса |
| **TypeScript** | Проверка типов, защита от опечаток в данных |
| **Tailwind CSS 4** | Стили |
| **ESLint** | Проверка качества кода |
| **node:test** | Тесты (встроен в Node, отдельная библиотека не нужна) |

**Почему Tailwind, а не CSS Modules.** Сайт состоит из множества мелких блоков
на одной странице. Tailwind держит отступы, размеры шрифтов и цвета в единой
шкале и не даёт стилям расползаться по десяткам файлов: правя вёрстку, вы видите
её оформление здесь же. Фирменные цвета и шрифты заданы один раз в
`src/app/globals.css` — менять их нужно только там.

Сторонних библиотек интерфейса намеренно нет: меньше кода грузится в браузер.

## Установка

```bash
npm install
```

Затем создайте файл настроек из примера:

```bash
cp .env.example .env.local
```

Файл `.env.local` в систему контроля версий не попадает — настоящие ключи
храните только в нём.

## Переменные окружения

Все значения задаются в `.env.local`. Полный список с пояснениями — в
`.env.example`.

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта. Влияет на canonical, sitemap.xml и превью в соцсетях. Без слэша в конце |
| `NEXT_PUBLIC_ALLOW_INDEXING` | `true` — сайт открыт для поисковиков. Любое другое значение — закрыт. **На тестовой площадке всегда оставляйте закрытым** |
| `LEAD_WEBHOOK_URL` | Куда уходят заявки с формы |
| `LEAD_WEBHOOK_TOKEN` | Токен доступа к приёмнику заявок |
| `LEAD_TRANSPORT` | `webhook` или `mock`. `mock` работает только при разработке |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | Номер счётчика Яндекс Метрики |

**Секреты и токены в код не вписываются.** Только в `.env.local` или в настройки
хостинга.

## Как изменить тексты

Заголовок первого экрана, описание школы, названия кнопок — файл
`src/content/site.ts`.

Например, поменять заголовок на главной:

```ts
hero: {
  titleLines: ['Научим ребёнка', 'уверенно плавать'],  // ← две строки заголовка
  subtitle: 'Групповые занятия 45 минут для детей...',
},
```

Сохраните файл — страница обновится сама.

---

## Как изменить контакты

Файл `src/content/contacts.ts`. Телефон указывается дважды: как его видят люди
и как он работает при нажатии.

```ts
phone: {
  display: '+7 991 229-99-77',   // ← что видит посетитель
  href: 'tel:+79912299977',      // ← только цифры и плюс, без пробелов
},
```

Адрес, ссылки на VK, Telegram и MAX — в том же файле.

---

## Как изменить цены

Файл `src/content/prices.ts`. Найдите нужный тариф и поменяйте `amount`:

```ts
{
  id: 'trial',
  title: 'Разовое / пробное',
  amount: 1100,          // ← цена в рублях, только число, без пробелов и знака ₽
  featured: false,       // ← true выделит карточку цветом
},
```

Знак ₽ и разделение разрядов подставляются сами. Приписка про скидку — в
переменной `pricesNote` внизу файла.

---

## Как изменить расписание

Файл `src/content/schedule.ts`. Каждое занятие — отдельный блок:

```ts
{
  id: 'mon',                 // короткое имя латиницей, должно быть уникальным
  day: 'Понедельник',
  time: '19:45',
  note: 'Групповая тренировка в бассейне',
},
```

Чтобы **добавить** занятие — скопируйте блок целиком и поменяйте значения.
Чтобы **убрать** — удалите блок вместе с фигурными скобками и запятой.

---

## Как добавить тренера

1. Положите фотографию в `public/media/coaches/`. Имя файла — латиницей,
   например `ivanov-petr.jpg`. Желательно квадратное фото от 1000×1000.
2. Откройте `src/content/coaches.ts` и скопируйте существующий блок, поменяв
   значения:

```ts
{
  id: 'ivanov-petr',
  name: 'Иванов Пётр Сергеевич',
  role: 'Тренер по плаванию',
  bio: ['Первый абзац.', 'Второй абзац.'],
  specialities: ['Обучение с нуля', 'Техника'],
  photo: {
    src: '/media/coaches/ivanov-petr.jpg',   // путь от папки public
    alt: 'Пётр Иванов — тренер школы PRIME SWIM',
    width: 1000,     // ← реальные размеры файла в пикселях
    height: 1000,
  },
},
```

`width` и `height` должны совпадать с настоящими размерами файла — иначе при
загрузке страницы вёрстка будет прыгать.

---

## Как заменить фотографию

1. **Сохраните оригинал** в `media-source/originals/from-disk/` — не удаляйте
   и не изменяйте его.
2. Положите рабочую копию в подходящую папку (`pool/`, `gallery/`,
   `coaches/`, `brand/`) с понятным именем латиницей.
3. Пропишите её в `src/content/media.ts`, указав **реальные** размеры и
   осмысленный `alt` — описание того, что на фото, для незрячих посетителей и
   поисковиков.
4. Обновите `public/media/media-manifest.json` — откуда взято фото и где
   используется.

Уменьшать или конвертировать фото вручную не нужно: сайт сам отдаёт нужный
размер и современный формат под каждое устройство. **Не растягивайте** мелкие
изображения — лучше отметить, что нужна замена.

## Как добавить видео

В галерее уже показаны три коротких клипа с тренировок (`src/components/sections/Gallery.tsx`) —
каждый со своей обложкой-заставкой (poster) и стандартными элементами
управления браузера, без автовоспроизведения и звука.

Чтобы добавить новый клип:

1. Сожмите видео (файлы в репозитории перекодированы через ffmpeg —
   `libx264`, CRF 27–28 — чтобы не раздувать статическую сборку) и положите
   в `public/media/video/`.
2. Сделайте статичную обложку-заставку и положите её туда же.
3. Пропишите оба файла в массиве `galleryVideos` в `src/content/media.ts`.
4. Обновите `public/media/media-manifest.json`.

## Как сейчас устроена запись на занятие

**Формы на сайте нет — это осознанное решение.** Бот и CRM пока не подключены,
поэтому заявке некуда было бы уходить. Вместо формы блок «Запишите ребёнка на
пробное занятие» предлагает три рабочих способа связи: Telegram, MAX и телефон.

Форма уже написана и протестирована, она просто скрыта. **Как только вы укажете
адрес приёмника заявок в `LEAD_WEBHOOK_URL`, форма появится на странице сама** —
трогать код не нужно. Пока адреса нет, посетитель физически не может отправить
заявку в никуда.

Проверить, что получится, можно локально: добавьте в `.env.local` строку
`LEAD_TRANSPORT=mock` — форма появится, но никуда отправлять не будет.

## Подключение CRM

Отправка заявок вынесена в отдельный файл `src/lib/crm.ts` — страницы менять не
придётся.

**Простой вариант (вебхук).** Если CRM или Telegram-бот умеет принимать
данные по ссылке, достаточно указать её в `.env.local`:

```
LEAD_WEBHOOK_URL=https://адрес-приёмника
LEAD_WEBHOOK_TOKEN=ваш_токен
```

Заявка уходит методом POST в формате JSON:

```json
{
  "name": "Мария",
  "phone": "79912299977",
  "program": "beginners",
  "comment": "Ребёнку 8 лет",
  "submittedAt": "2026-08-23T10:00:00.000Z"
}
```

**Сложный вариант (своя CRM).** Добавьте свою реализацию в `src/lib/crm.ts`
рядом с `webhookTransport` и укажите её в функции `getLeadTransport()`.

**Важно про надёжность.** Если отправка не удалась, посетителю честно
показывается сообщение об ошибке с предложением позвонить — ложного «Заявка
отправлена» не будет. Персональные данные в журналы сервера не пишутся.

## Подключение аналитики

Счётчик Яндекс Метрики подключён. Номер задаётся переменной окружения — он не
секрет и всё равно виден в исходнике страницы:

```
NEXT_PUBLIC_YANDEX_METRIKA_ID=12345678
```

Если переменная пуста, на страницу не попадает ни одного стороннего скрипта.

**Счётчик включается только после согласия на cookie.** Метрика ставит cookie и
обрабатывает IP-адрес, поэтому до ответа на баннер её тега в разметке нет вовсе
(см. `src/lib/consent.ts`). Цена этого решения — часть визитов в отчёты не
попадает; это осознанный размен на соблюдение закона, а не ошибка.

### Цели

Часть целей код отправляет сам, часть достаточно завести в интерфейсе Метрики.

**Цели типа «JavaScript-событие».** Имя цели в Метрике должно совпадать с
идентификатором из `src/lib/analytics.ts` посимвольно:

| Идентификатор | Что считает |
|---|---|
| `cta_booking` | нажатие кнопки «Записаться» в шапке, на первом экране и в нижней панели |
| `cta_schedule` | нажатие второй кнопки первого экрана |
| `click_phone` | нажатие на номер телефона в любом месте сайта |
| `click_telegram` | переход в Telegram |
| `click_max` | переход в MAX |
| `click_vk` | переход во ВКонтакте |
| `click_route` | нажатие «Построить маршрут на Яндекс Картах» |
| `view_contacts` | блок контактов доехал до экрана (один раз за загрузку) |
| `lead_submitted` | форма записи заполнена и отправлена |

Разметка кликов держится на атрибуте `data-goal`: обработчик один на весь
документ, поэтому новую отслеживаемую ссылку достаточно пометить атрибутом,
подключать ничего не нужно.

**Цели типа «Посещение страниц».** Заводятся в интерфейсе Метрики, кода не
требуют — просмотр стоимости и расписания это отдельные адреса:

| Цель | Условие |
|---|---|
| Просмотр стоимости | `url`: содержит `/price/` |
| Просмотр расписания | `url`: содержит `/raspisanie/` |

Заводить для них ещё и JavaScript-событие не нужно: одно и то же действие
считалось бы дважды.

## Тестовое размещение

Хостинг ещё не выбран, поэтому проект к конкретной площадке не привязан.

**Обязательное условие:** на тестовой площадке индексация должна быть закрыта.

```
NEXT_PUBLIC_SITE_URL=https://адрес-тестовой-площадки
NEXT_PUBLIC_ALLOW_INDEXING=false
```

При `NEXT_PUBLIC_ALLOW_INDEXING=false` файл robots.txt автоматически запрещает
поисковикам обход сайта, а страницы помечаются как неиндексируемые. Проверить
можно, открыв `/robots.txt` — там должно быть `Disallow: /`.

## Production-развёртывание

1. Установите переменные окружения на боевой площадке:

   ```
   NEXT_PUBLIC_SITE_URL=https://primeswim.ru
   NEXT_PUBLIC_ALLOW_INDEXING=true
   LEAD_WEBHOOK_URL=<адрес приёмника заявок>
   LEAD_WEBHOOK_TOKEN=<токен>
   ```

2. Соберите и запустите:

   ```bash
   npm ci
   npm run build
   npm run start
   ```

3. **Проверьте после запуска:**
   - `/robots.txt` содержит `Allow: /`, а не `Disallow: /`;
   - `/sitemap.xml` открывается и содержит боевые адреса;
   - форма отправляется и заявка реально доходит до получателя;
   - работает HTTPS;
   - страница `/policy` открывается, реквизиты оператора заполнены.

**Переключение домена, изменение DNS и отключение Tilda выполняются только по
отдельному решению владельца сайта.**

## Откат

Сайт на Tilda не изменялся, поэтому вернуться к нему можно в любой момент.

**Если проблема обнаружена после переключения домена:**

1. Верните записи DNS на прежние значения Tilda — сохраните их **до**
   переключения.
2. Дождитесь обновления DNS (обычно до нескольких часов).
3. Убедитесь, что действующий сайт открывается и формы работают.

**Если проблема в новой версии, но домен ещё не переключён:** просто продолжайте
работу на Tilda, ничего откатывать не нужно.

**Откат кода** выполняется возвратом к предыдущей версии в системе контроля
версий и повторной сборкой.
